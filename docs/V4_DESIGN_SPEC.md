# Supported SAM3 + VLM counting MVP

This document is authoritative for the supported `sam3_vlm.mvp` workflow. The older M8 modules, configurations, experiments, and related documents remain historical research code. The previous specification is preserved as [HISTORICAL_M8_DESIGN_SPEC.md](HISTORICAL_M8_DESIGN_SPEC.md). This MVP does not run them.

## Scope and interface

One run takes one RGB image, a fixed target description, frozen `Config`, a SAM3 adapter, and optionally a VLM adapter. The controller owns a node dictionary and all state changes. Only SAM3 masks create nodes. A VLM proposes positive target searches; it neither detects nor counts. All persistent masks and integer, exclusive-end regions use original-image coordinates. In the default mode, the full-image target search runs first. Strong SAM3 seed detections can supply positive box exemplars for one refinement search. A dense first pass can trigger ROI-guided overlapping tiles. Optional fixed bootstrap regions follow. Each prompt-region search is one attempted SAM3 request. No confounder actions, manual exemplars, merging, action bank, saturation rule, or hidden retries are used.

The supported entry point is `python -m sam3_vlm.mvp.cli IMAGE TARGET --config configs/mvp.json --output result.json --masks masks.npz`. `--masks` is optional. The CLI initializes models before entering `Controller.run`; reported runtime measures the run, and adapter timings measure model requests. Qwen uses `QWEN_BASE_URL`, `QWEN_MODEL`, and optional `QWEN_API_KEY`. The OpenAI-compatible SDK has retries disabled. The Python API accepts compatible fake adapters for deterministic tests.

### FSCD-147 VLM-first benchmark mode

`configs/fscd147.json` sets `vlm_first=true`, zero bootstrap regions, exemplar refinement, and adaptive tiling. This is a separate mode of the same controller. The first model request is to Qwen with the whole image and the split's class name. It must return one ROI (`null` means the full image), `tile_mode` (`auto` or `force`), and one or more positive SAM3 search actions. No SAM3 search runs before this plan. The controller rejects malformed ROIs, searches outside the selected ROI, and empty initial plans. Later Qwen actions also stay inside the ROI. Qwen may select `force` for small or crowded objects; this runs overlapping tiles even when the first SAM3 search returns no detections. In `auto` mode, the existing density score decides, using the VLM ROI's area. Tile size and grid are based on the ROI dimensions, and every tile remains inside it. Strong SAM3 detections from the initial search supply the optional conditioned exemplar refinement search inside the ROI; ground-truth exemplar boxes are never used.

`sam3_vlm.mvp.fscd_cli run DATASET_ROOT OUTPUT_DIR --split val` streams prediction JSONL and does not read annotations. It requires the original FSC-147 split/class files and images. `sam3_vlm.mvp.fscd_cli evaluate DATASET_ROOT OUTPUT_DIR/predictions.jsonl --split val --coco-output detections.json` separately reads FSC points and FSCD `instances_val.json` / `instances_test.json`. It uses FSCD box counts for MAE/RMSE and emits predicted hard-count boxes in COCO format for the paper's detection evaluator. A missing or partial image suppresses split-level metrics and COCO export. Keep ROI, tiling, prompting, and thresholds frozen after validation before measuring the test split. This mode has mock-adapter behavioral tests; its real-model quality and comparative accuracy remain unmeasured.

The historical fruit pilot runner also exposes this controller as arm `F_VLMFirst_AdaptiveROI` in `--pilot-suite final-af`, appended to its original A–E arms. It uses the same images and count ground truth but applies the fruit-on-tree scope in both VLM planning calls. F's output and hard-belief count come from the MVP controller; legacy M8 replay validation applies only to A–E. See [M8_FINAL_AF_FRUITS.md](M8_FINAL_AF_FRUITS.md) for the run and count-type comparison.

## Bootstrap refinement and adaptive tiling

The initial full-image target search is always text-only. Its accepted nodes are the only input to the density decision. Nodes scoring below `adaptive_density_seed_score` (default 0.5) do not drive tiling. Strong nodes scoring at least `exemplar_min_score` (default 0.6) supply at most `exemplar_max_count` (default 5) positive boxes, sorted by score, belief, then node ID. When enabled and at least one seed exists, the controller makes one additional full-image SAM3 request with the same target text and these positive boxes. This is a deliberate exception to same-prompt/region duplicate rejection. The controller reselects strong boxes after refinement and passes only fully contained boxes to each subsequent tile. The SAM3 adapter converts them to crop-local coordinates. These are SAM3-generated pseudoexemplars, never annotations or VLM-created objects. Conditioned searches add positive evidence but their misses do not penalize existing nodes.

The tiling planner follows the image method in the supplied SAM3Count paper and its [official image implementation](https://github.com/Joan947/SAM3Count/blob/main/evaluate_fscd147.py). With cleaned Stage-1 boxes, it computes box-area coverage `c`, count `N`, and `size_score = 1 - min(mean_box_area / (0.1 * image_area), 1)`. The density score is `0.3*c + 0.5*min(N/50,1) + 0.2*size_score`. Tiling activates above `adaptive_density_threshold` (default 0.69). The padded union of Stage-1 boxes defines the ROI, with 4% padding per axis or at least 16 pixels. The reference implementation's activated `SMALL` regime uses a target 6-column by 4-row grid, square tile size `clip(int(max(W/6,H/4)),97,1024)`, and 25% overlap. Generate the overlapping grid over the whole image, retain every tile with positive ROI intersection, and search retained tiles in row-major order. A tile identical to an already completed full-image prompt is skipped. Each tile consumes one SAM3 request and uses the same original-image mask association and belief rules. The plan and density components appear in `result.tiling`; actions trace each executed tile. `enable_exemplar_refinement` and `enable_adaptive_tiling` are independent switches. `configs/mvp.json` enables both and allows 64 SAM3 requests.

The paper's image pipeline is text-only and does not specify pseudoexemplar refinement. The exemplar pass here restores the earlier V4 controller's strong-seed positive-box method. The public SAM3Count code also has a separate heuristic gate for whether Stage-1 detections make a reliable ROI; this MVP uses the simpler cleaned-score filter above and omits that gate. Its published tile filter effectively retains any positive ROI overlap. The MVP uses its persistent-node mask IoU/IoM association, plus box IoU above `tile_box_iou_threshold` (default 0.5) for tile detections, instead of a separate final NMS pass. Multiple eligible nodes remain ambiguous and are discarded. This retains a single counting rule across full-image, refined, tiled, and VLM searches. The paper mentions recursive retiling at detector capacity; the public image implementation logs that condition without executing another recursion. This MVP currently performs one adaptive tiling level.

## VLM action contract

One VLM response is JSON with exactly one top-level `actions` list. Each action has exactly `prompt` (nonempty string) and `region` (`null` or four integer image coordinates). For example:

```json
{"actions":[{"prompt":"small green fruit","region":null},{"prompt":"green fruit","region":[0,0,512,512]}]}
```

`max_actions_per_vlm_call` sets the per-response maximum. Setting it to 1 gives the single-action ablation; setting it above 1 enables batches. Run both with the same images, model settings, SAM3 budget, VLM budget, prompts, and counting rule, then compare errors, calls, and elapsed time. Generated actions can differ, so repeat runs if model sampling is nondeterministic. No full dataset run is implied.

Malformed JSON or a malformed top-level object rejects the response. In a well-formed list, invalid entries are rejected individually; excess entries are rejected as `batch_truncated`. Exact duplicate means normalized prompt (trim, lowercase, collapse whitespace) plus exact region; the deliberate conditioned exemplar-refinement pass is the sole exception. Completed searches and earlier accepted entries in the same batch block duplicates; the same prompt in another region is valid. Failed searches can be retried. Every proposal and rejection is traced. Accepted entries are recorded as pending before execution, then execute sequentially. Each observation is applied before the next action. A final permitted VLM response still executes all accepted actions allowed by remaining SAM3 and runtime budgets. Unexecuted accepted actions remain pending and are listed in `unexecuted_batch`.

The VLM receives the original image, target, nodes with boxes and beliefs, the last 12 search summaries, the last 12 successfully searched regions and total successful search count, remaining budgets, and at most `max_candidate_crops` node crops closest to the hard threshold (node ID breaks ties). Full coverage remains in controller history. Ground truth is never supplied.

## Detection, association, and belief

The SAM3 adapter crops one region, makes one model request, and places binary masks back on the original image. The controller discards empty or malformed masks, nonfinite/out-of-range scores, and scores below threshold. It processes remaining detections by descending score, descending mask area, then source order. A detection matches a node if mask IoU is at least `match_iou_threshold`, or mask IoM is at least `match_iom_threshold` with smaller/larger area ratio at least `min_match_area_ratio`. Tile detections may also match by box IoU above `tile_box_iou_threshold`. Extreme containment is discarded as ambiguous. A detection matching multiple nodes is also discarded. Accepted detections attach to one node or create one. The largest accepted mask is canonical; ties use higher score and then earlier detection. Nodes are never automatically merged or deleted.

Each node stores the maximum positive SAM3 score per normalized prompt. Sort these scores high to low and compute `E+ = sum(discount**j * score[j])`. For each normalized prompt there is at most one active non-retrieval penalty. Let `E- = sum(discount**j for j in range(number_of_active_penalties))`. Belief is `sigmoid(logit(prior) + log(evidence_base) * (E+ - negative_strength * E-))`. It is a heuristic support score, not a calibrated probability. Default prior is 0.25, base 9, discount 0.5, negative strength 0.5. Both bootstrap-only and adaptive runs use soft count `sum(beliefs)` and hard count `number of beliefs >= hard_count_threshold`.

A successful unconditioned target search penalizes only nodes that existed before that observation, whose canonical mask is at least `negative_coverage` (default 0.9) inside the searched region, and that were neither retrieved nor touched by an ambiguous detection. A missed prompt adds one penalty at most, regardless of the number of eligible successful regions. Repeating the prompt and region after completion is rejected; repeating the prompt elsewhere may search, but does not stack another penalty. A later accepted retrieval of that node under the same prompt clears its penalty and may replace its strongest positive score. Different prompt penalties are geometrically discounted. Empty successful unconditioned searches can therefore lower eligible existing beliefs. Exemplar-conditioned misses, unrelated regions, failed calls, replayed observations, discarded ambiguous matches, and newly created nodes in that observation do not receive a penalty. The action trace gives the source action and belief before/after for each update. Reapplying an action ID is a no-op.

Positive evidence can raise belief; non-retrieval can lower it. Counts can move in either direction and still omit undiscovered objects. No calibration or independent-evidence claim is made.

## Budgets, failures, and results

Attempted and successful SAM3/VLM calls are separate counters. A returned VLM response counts as a successful model request even if its JSON or proposals are invalid; parsing and action validation are separate trace outcomes. Budgets and deadline are checked before every model request and each batch item. One in-flight request may overrun the deadline. Boundary stop precedence is time, then SAM3, then VLM. Invalid final responses with no accepted action end as `no_valid_action`; exhausted VLM budget after executing its accepted batch ends as `qwen_budget`. A failed request ends as `error` without applying its partial output. Prior successful observations remain. Interrupted bootstrap or batch actions are listed, and the result is partial. Counts are null until one SAM3 search succeeds; a successful empty search gives zero counts. Runtime covers controller work from run entry, and model timings report request time separately. Models constructed before entry are outside that measured interval.

Evaluation is separate: `sam3_vlm.mvp.evaluate_count(result, ground_truth_count)` computes post-run errors without mutating the result. Keep the same evaluation protocol across action-count ablations. The JSON output includes boxes, beliefs, evidence, action trace, counters, stop reason, runtime, and metadata. Optional NPZ contains canonical masks.

## Limits

Mask matching can reject merged or severely occluded objects, and box-based tile association can merge nearby objects whose boxes overlap heavily. Similar prompts remain correlated despite grouping and discounting. Search coverage records successful requests, not exhaustive visual coverage. Real-model quality, latency, and belief parameters require empirical study; local fake-adapter tests do not establish them.
